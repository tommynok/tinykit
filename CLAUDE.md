# Инструкция и контекст проекта TinyKit (CLAUDE.md)

Данный документ служит единым источником контекста, правил разработки, терминологии и стилистики для ассистентов и разработчиков проекта **TinyKit** (форк репозитория `Order52/tinykit`).

---

## 1. Роли и ограничения взаимодействия

* **Роль пользователя**: архитектор и тестировщик.
* **Терминальные команды**: пользователь **не работает в консоли** (PowerShell, bash, git, gradle). Все операции с кодом, git-коммиты, пуши и запуск сборок выполняет исключительно агент.
* **Зрительные особенности пользователя**: пониженная контрастная чувствительность (слабое зрение).
  * Текст в светлой теме обязан быть **чисто чёрным (`#000000`)** или глубоким тёмным (`#111111`).
  * Недопустимы серые надписи типа `#777777`, низкий `alpha` (прозрачность) для отключённых элементов (вместо `alpha = 0.4` используется `1.0f` с читаемым цветом).
  * Размеры шрифтов должны оставаться комфортными для чтения (не менее 10.5–12sp для навигации).
* **Совместимость тестовых сборок**:
  * Репозиторий содержит постоянный ключ подписи [signing/debug.keystore](signing/debug.keystore), действительный до 2054 года.
  * Релизные APK в CI/CD ([.github/workflows/build.yml](.github/workflows/build.yml)) подписываются этим ключом, что гарантирует установку каждого нового тестового APK прямо поверх предыдущего без потери настроек и данных.

## 2. Архитектура локализации

Локализация в TinyKit состоит из двух независимых уровней:

1. **Системный уровень Android (OS SystemUI)**:
   * Файлы: [app/src/main/res/values-ru/strings.xml](app/src/main/res/values-ru/strings.xml) и `fastlane/metadata/android/ru-RU/`.
   * Отвечает за системные компоненты, объявленные в манифесте: 25 плиток быстрых настроек (Quick Settings tiles), виджет рабочего стола и метаданные магазинов (F-Droid).
2. **Внутриприкладной уровень (Runtime UI Engine)**:
   * Движок: [app/src/main/java/io/github/order52/tinykit/Tr.java](app/src/main/java/io/github/order52/tinykit/Tr.java).
   * Словарь: [app/src/main/assets/i18n/ru.tsv](app/src/main/assets/i18n/ru.tsv) (1165 строковых пар, формат `English\tRussian`).
   * Строки в Java-коде переводятся вызовом `Tr.t("...")`.
   * **Важно**: в `Tr.java` поиск ключей ведётся прямым разбиением по символу табуляции `line.indexOf('\t')`. Запрещено оборачивать строки в кавычки RFC 4180. Начальные и конечные пробелы ключей и переводов должны совпадать 1:1.
   * `MainActivity.onCreate()` обязательно вызывает `Tr.init(this)` для перезагрузки словаря при смене языка или обновлении APK без выгрузки процесса из памяти.

## 3. Стилистический гайдлайн русской локализации (Anti-Calque Guide)

### Главные принципы
1. **Отказ от кальки с английского предлога `for`:**
   * В английском языке предлог `for` вездесущ (*for apps*, *for each app*, *for selected apps*).
   * В русском языке вместо предлога «для» следует использовать:
     * **Дательный падеж («кому/чему?»)**: *«блокировка интернета приложениям»*, *«назначить язык приложению»*, *«запретить доступ выбранным приложениям»*.
     * **Глагольное управление («от чего?»)**: *«отключение приложений от Wi-Fi»*.
     * **Предлог «по»**: *«блокировка интернета по приложениям»* (по аналогии со стандартным *«трафик по приложениям»* в Android).
2. **Борьба с канцеляритом (нанизыванием родительного падежа):**
   * Избегать длинных цепочек существительных: вместо *«Блокировка интернета для выбранных приложений»* использовать *«Запрет доступа к Wi-Fi и мобильной сети выбранным приложениям»*.
3. **Устранение тавтологий между заголовком и подзаголовком:**
   * Заголовок и поясняющий подзаголовок на экране не должны использовать одинаковые слова (например, повтор слова «интернет» дважды подряд).
4. **Консистентность системной терминологии Android:**
   * «Для разработчиков» (Developer options).
   * «Быстрые настройки» / «Шторка» (Quick Settings / Quick panel).
   * «Буфер обмена» (Clipboard).
   * «Рабочий профиль» (Work profile).

## 5. UI и вёрстка таб-бара (FitTabs)

* В [MainActivity.java](app/src/main/java/io/github/order52/tinykit/MainActivity.java) метод `fitTabs()` динамически масштабирует текст всех 5 вкладок по самому длинному слову.
* **Ограничение**: длина названий вкладок не должна превышать 11–12 символов.
* **Минимальный порог шрифта**: зафиксирован на уровне `10.5sp` (дефолтный размер 12sp).

## 6. Процедура сборки и проверки репозитория

1. Проверка целостности:
   ```bash
   scripts/check-repo.sh
   ```
   Должно возвращать `repo checks passed`.
2. Коммит и доставка в GitHub Actions:
   ```bash
   git add -A
   git commit -m "..."
   git push origin main
   ```
3. Мониторинг сборки через GitHub Actions API. По завершении пользователю предоставляется прямая ссылка на запуск и скачивание APK.
